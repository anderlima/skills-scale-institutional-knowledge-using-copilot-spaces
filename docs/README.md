# OctoAcme Project Management Documentation

Welcome to the OctoAcme project management process documentation. This guide gives teams a single starting point for how we initiate, plan, execute, communicate, release, and improve projects.

## Overview

OctoAcme follows a lightweight, repeatable project management approach designed to keep delivery focused on customer value while maintaining clarity, accountability, and measurable progress. Our process emphasizes:

- Customer-first prioritization
- Iterative delivery of testable increments
- Clear ownership across product, project, and engineering roles
- Risk visibility and stakeholder communication
- Continuous improvement through retrospectives and feedback loops

## Process Lifecycle Summary

OctoAcme projects move through the following lifecycle:

Initiation → Planning → Execution & Tracking → Risk Management & Communication → Release & Deployment → Close & Retrospective

Each phase builds on the previous one and helps the team move from an idea to a successful launch and a learning cycle that improves future work.

## Key Roles

- Project Manager (PM): coordinates delivery, schedules, risks, documentation, and communication.
- Product Manager / Product Lead: defines outcomes, prioritizes the backlog, and measures success.
- Developers: design, implement, test, and deliver the product or service.
- QA / Testing: validates quality, acceptance criteria, and release readiness.
- Stakeholders: provide input, approval, and business context.

## How to Use These Docs

New team members should begin with the project overview, then move to the relevant phase for their current work:

1. Start with the [Project Management Overview](./octoacme-project-management-overview.md) for the big picture.
2. Use [Project Initiation](./octoacme-project-initiation.md) when a project is just beginning.
3. Use [Project Planning](./octoacme-project-planning.md) to create milestones, scope, and backlog items.
4. Use [Execution & Tracking](./octoacme-execution-and-tracking.md) during day-to-day delivery.
5. Use [Risk Management & Communication](./octoacme-risks-and-communication.md) whenever issues, blockers, or dependencies need visibility.
6. Use [Release & Deployment](./octoacme-release-and-deployment.md) before shipping changes.
7. Use [Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md) to close the loop after each milestone or release.

## Common Project Artifacts

Across the lifecycle, OctoAcme teams typically maintain the following:

- Project Charter / One-pager
- Roadmap and release plan
- Sprint or iteration backlog
- Acceptance criteria and Definition of Done
- Risk register
- Status updates and stakeholder communications
- Retrospective notes and action items
